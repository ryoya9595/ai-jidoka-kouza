# Claude Code 向け手順書：決まった時間に自動で動かす（日報のオートメーション）

> この手順書は **Claude Code が読んで実行するためのもの** です。受講生と会話しながら、上から順に進めてください。
> RISE「AI自動化講座」12回目の配布物。受講生は「このURLを読んで、書いてある通りに進めてください」と送るだけ。
> この URL（https://ryoya9595.github.io/ai-jidoka-kouza/files/12-nippo-routine.md）を渡されたら、`curl -fsSL <URL>` で全文を取得して読む。**作業フォルダには保存しない**（画面に出して読むか、一時フォルダに置く）。
> 前提：第10回の「日報スキル」（`.claude/skills/my-nippo/SKILL.md` と CLAUDE.md の「日報のためのメモ」）が入っていること。無ければ先に https://ryoya9595.github.io/ai-jidoka-kouza/files/10-nippo-skill.md を読んで入れる。
> 画面の名前が手順書と違うときは、公式ドキュメント（クラウド：https://code.claude.com/docs/en/routines ／ ローカル：https://code.claude.com/docs/en/desktop-scheduled-tasks）を `curl` で読み直して最新の名前で案内する。

## 0. ゴール

**毎日決まった時間に、日報が自動で作られて GitHub に上がる** ようにする。受講生が何もしなくても、Claude Code が `/my-nippo` を実行してくれる。

使うのは Claude Code の **ルーティン（Routines）** 機能。2種類ある：

| | クラウド（リモート） | ローカル |
|---|---|---|
| どこで動く | Anthropic のサーバー | 自分のパソコン |
| パソコンの電源 | **閉じていても・切れていても動く** | **起動中・アプリが開いているときだけ** |
| 使えるもの | **GitHub に保管してある作業フォルダの中身だけ** | パソコンの中のファイル・ログイン中のブラウザも使える |
| 向いている作業 | 日報など、作業フォルダの中だけで完結するもの | X を見てニュースを集めるなど、ブラウザが要るもの |

今回の日報は **クラウド** で作る（パソコンを閉じていても動くため）。この講座で作業フォルダを GitHub につないだのは、このためでもある。

- クラウドのルーティンは、実行の間隔が **1時間に1回まで**。Pro プランでは **1日5回まで** の上限がある（※撮影時点の数字。変わることがあるので、違っていたら公式ドキュメントの「Usage and limits」を確認する）。毎日1回の日報なら十分

## 1. 守ること（最優先）

- **受講生はパソコン初心者。** 専門用語を避け、短く・やさしい日本語で話す。**1〜3手順ずつ** 出して「できた」を待つ。
- **ルーティンの作成画面は受講生本人が操作する。** Claude Code は項目ごとに「何を選ぶか・何を書くか」を案内する（ログイン・ボタン押しは本人）。
- **パスワード・トークン・APIキーをルーティンの指示欄や作業フォルダに書かない。**
- **コネクタ（Connectors）は今回使わない。** 最初からオンになっているものは外してもらう（オンのままだと、自動実行中に Claude がそのサービスを許可なしで使えてしまうため）。
- クラウドで作られた日報は、`main` ではなく **`claude/` で始まるブランチ** に上がることがある。それは失敗ではない（「GitHubの最新を取り込んで」で取り込める）。
- ファイルの作成・編集は Write / Edit ツールで行う（Windows の PowerShell のリダイレクトは文字化けするので使わない）。文字コードは UTF-8。

## フェーズ1：事前チェック（読むだけ・何も変更しない）

Claude Code が自分で確認すること：

1. **日報スキルがあるか**：`.claude/skills/my-nippo/SKILL.md` がある／`CLAUDE.md` に「## 日報のためのメモ」がある
   - 無ければ、第10回の配布物（上の URL）を先に入れてから戻る
2. **作業フォルダが GitHub に上がっているか**：
   - `git status --short`（未保存の変更が無いか）
   - `git fetch origin` → `git log --oneline origin/main..main`（パソコンだけにあるコミットが無いか）
   - 変更や未送信があれば「クラウドから見えるように、先に GitHub に上げます」と伝えて、日本語のメッセージでコミット → `git push`
   - `gh repo view --json nameWithOwner,visibility,url` で **リポジトリ名（`ユーザー名/リポジトリ名`）** を控える。visibility が PRIVATE であることも確認
3. **スキルが GitHub 側にもあるか**：`git ls-tree -r origin/main --name-only | grep my-nippo` で `.claude/skills/my-nippo/SKILL.md` が出ること（出なければ上げ忘れ → 2 をやり直す）

受講生に確認してもらうこと（Claude GitHub App の許可）：

> 日報の自動化を作ります！まず1つ確認です。
> ブラウザで https://github.com/apps/claude/installations/new を開いて、`{リポジトリ名}` が **選ばれている（チェックが入っている）** か見てください。
> ・入っている → 「OK」と送ってください
> ・入っていない／画面が「Configure」になっている → `{リポジトリ名}` にチェックを入れて「Save」（または「Install」）を押してください

（第3回のフェーズ6でやった設定。これが無いと、ルーティンの作成画面でリポジトリが選べない）

## フェーズ2：クラウドのルーティンを作る（受講生がアプリで操作）

受講生に、Claude Code のアプリで次の通り進めてもらう。**1〜2項目ずつ** 案内して「できた」を待つ。

> それでは、自動実行の設定を作ります。Claude Code のアプリで一緒にやりましょう。

1. **ルーティンを開く**
   > Claude Code の左側のメニューから「**ルーティン**」（英語なら **Routines**）を開いてください。見つからなければ、メニューの「**その他**」（**More**）の中にあります。
2. **新しいルーティン → クラウド**
   > 「**新しいルーティン**」（**New routine**）を押して、「**クラウド**」（**Cloud**。「リモート」と出ることもあります）を選んでください。
3. **名前**
   > 名前（Name）に **毎日の日報** と入れてください。
4. **指示**
   > 指示（**Instructions**）の欄に、次の文をそのままコピーして貼ってください：
   >
   > --------------
   > /my-nippo を実行して、今日の日報を作ってください。できたらGitHubに上げてください
   > --------------
   >
   > 普段 Claude Code に話しかけるのと同じ書き方で大丈夫です。
5. **リポジトリ**
   > リポジトリ（Repositories）で、自分の作業フォルダ **`{リポジトリ名}`** を選んでください。
   > （出てこないときは、フェーズ1の Claude GitHub App の許可を見直します）
6. **環境**
   > 環境（Environment）は「**Default**」のままで大丈夫です。
7. **スケジュール（トリガー）**
   > 「**トリガーを選択**」（**Select a trigger**）で「**スケジュール**」（Schedule）→「**毎日**」（Daily）を選び、時刻を決めてください。
   > 例：22時。ぴったりの時刻（22:00）だと数分遅れて始まることがあるので、**22:07** のように少しずらすのがおすすめです。
   > 時刻は、ふだん作業を終えている時間にしてください（生活リズムに合わせて OK）。
8. **コネクタを外す**
   > 一番下の「**コネクタ**」（**Connectors**）に、最初からオンになっているものがあれば、**今回は使わないので全部外してください**（× や削除で外せます）。
9. **作成**
   > 「**作成**」（**Create**）を押してください。一覧に「毎日の日報」が出たら「できた」と送ってください。

## フェーズ3：今すぐ実行して確かめる

1. 受講生に案内する：
   > 一覧の「毎日の日報」を開いて、「**今すぐ実行**」（**Run now**）を押してください。
   > 実行の様子（セッション）が開くので、終わるまで1〜3分ほど待ちましょう。Claude が日報を作って GitHub に上げるところが見られます。
2. 終わったら、Claude Code（パソコン側）で確認する：
   - `git fetch --all --prune`
   - `git log --oneline main..origin/main`（main に直接上がった場合）
   - `git branch -r --list 'origin/claude/*'`（`claude/` ブランチに上がった場合）→ `git log --oneline main..origin/claude/<名前>` で「日報」のコミットがあるか見る
   - どちらにも無ければ、受講生に実行画面の最後の方（エラーが出ていないか）を読んでもらう → 付録へ
3. 日報が上がっていたら、**フェーズ4の「取り込み」をその場で1回やる**（受講生が「GitHubの最新を取り込んで」と言う練習）
4. 伝える：
   > 自動で日報ができました！🎉 これで毎日 {時刻} に、何もしなくても日報が作られます。
   > 緑のチェックは「動いた」という意味で、「日報ができた」とは別なので、最初の数日は実行の中身をのぞいてみてください。

## フェーズ4：毎日の使い方（2つの合言葉で回す）

クラウドの自動実行は **GitHub に保管してある作業フォルダ** を見て日報を作る。パソコンの中だけにある変更は見えない。だから：

| いつ | 受講生が言う言葉 | 何が起きるか |
|---|---|---|
| パソコンで作業を終えたとき | 「**GitHubに上げて**」 | その日の作業が GitHub に上がる → 夜のクラウド実行が日報に入れられる |
| 次の日、作業を始めるとき | 「**GitHubの最新を取り込んで**」 | クラウドが作った日報がパソコンの作業フォルダにも入ってくる |

受講生に伝える：

> 毎日の使い方は、第3回で覚えた2つの言葉だけです。
> ・作業を終えたら →「GitHubに上げて」（上げておかないと、その日の作業が日報に入りません）
> ・次の日の始めに →「GitHubの最新を取り込んで」（クラウドで作られた日報がパソコンにも入ってきます）

### 「GitHubの最新を取り込んで」で何をするか（Claude Code 向け）

作業フォルダの `CLAUDE.md`「GitHub との同期（合言葉）」に書いてある通りに動く。おさらい：

1. 未保存の変更があれば `git add -A` → `git commit -m "作業途中の保存"`
2. `git pull --no-rebase` で main を最新にする（クラウドが main に直接上げていれば、ここで日報が入る）
3. `git fetch --all --prune` → `git branch -r --list 'origin/claude/*'` で `claude/` ブランチを探す。あれば `git log --oneline main..origin/claude/<名前>` で「いつ・何を変えたか」を短く見せる
4. 取り込んでいいか聞いてから `git merge --no-edit origin/claude/<名前>` → `git push`。取り込んだブランチは消してよいか聞き、OK なら `git push origin --delete claude/<名前>`
5. 衝突したら、どちらを残すか聞く（勝手に消さない）。日報は「`## 日報`より下だけ書き直す」決まりなので、たいていは両方残して直せる

なぜ `claude/` ブランチに上がるのか：クラウドの Claude Code は、安全のために **自分の変更を `claude/` で始まるブランチに送る** のが基本動作（指示があれば main にも送れる）。日報スキルには「main に送れなければ `claude/` ブランチに送れば成功」と書いてあるので、どちらでも取り込めるようになっている。

## フェーズ5：ローカルのルーティン（参考・必要な人だけ）

パソコンの中のファイルや、ログイン中のブラウザを使う作業（例：毎朝 X を見て AI ニュースを集める）は、**ローカル** で作る。作り方はほぼ同じ：

1. 「ルーティン」→「新しいルーティン」→「**ローカル**」（**Local**）を選ぶ
2. 項目：名前（Name）／説明（Description）／指示（Instructions）／指示欄の下で **作業フォルダ（folder）** を選ぶ／スケジュール（Schedule：手動・毎時・毎日・平日・毎週）
3. 「作成」→ 一度「今すぐ実行」して、許可を聞かれたら「常に許可」を選んでおく（次回から止まらずに動く）

ローカルは **パソコンが起動していて、Claude Code のアプリが開いているときだけ** 動く。スリープ中の分は飛ばされる（起きたときに、直近の1回分だけ追いかけて実行される）。だから：

- Claude Code の **設定 → このコンピュータ（This computer）→ システム（System）→「コンピュータをスリープさせない」（Keep computer awake）** をオンにしておくと安心
- **ノートパソコンはふたを閉じるとスリープする**（この設定でも防げない）。ふたは開けたまま、電源につないでおく

使い分けの目安：

- パソコンを閉じていても動いてほしい → **クラウド**
- パソコンの中のファイル・ログイン中のブラウザを使う → **ローカル**

## 付録：うまくいかないとき

| 症状 | 原因 | 対処 |
|---|---|---|
| 作成画面でリポジトリが出てこない | Claude GitHub App に作業フォルダを許可していない | https://github.com/apps/claude/installations/new で `{リポジトリ名}` を追加（第3回フェーズ6） |
| 「ルーティン」がメニューに無い | アプリが古い／会社のアカウントで無効 | アプリを最新にする。https://claude.ai/code/routines からも同じものが作れる。会社のアカウントは管理者に相談 |
| 実行は緑なのに日報が無い | 「動いた」≠「日報ができた」 | 実行の中身（セッション）を開いて最後の方を読む。「今日はまだ記録がありません」なら、その日 GitHub に上げた変更が無かっただけ |
| `/my-nippo` が見つからないと出る | スキルが GitHub に上がっていない | `git ls-tree -r origin/main --name-only \| grep my-nippo` で確認 → 無ければ「GitHubに上げて」 |
| 日報が `claude/…` ブランチにある | クラウドの基本動作（失敗ではない） | 「GitHubの最新を取り込んで」で取り込む（フェーズ4） |
| 日報の日付が1日ずれる | クラウドの時計は日本時間ではない | 日報スキルは `TZ=JST-9` で日本時間を出す決まり。SKILL.md がその書き方か確認 |
| 決まった時間に動かない | 1時間に1回・1日の上限／GitHub との接続が切れた | 時刻をずらす。https://claude.ai/code/routines で GitHub をつなぎ直す（切れたままだと3日で止まる） |
| ローカルのルーティンが飛ばされる | パソコンがスリープ／アプリを閉じていた | 「コンピュータをスリープさせない」をオン。ふたを閉じない。起きたとき直近1回だけ追いかけて動く |
| 「上限に達しました」と出る | プランの上限 | 時間をおいて再実行。回数を減らす（毎日1回なら通常は足りる） |
