# Claude Code 向け手順書：自分用の「講座解説スキル」を作る

> この手順書は **Claude Code が読んで実行するためのもの** です。受講生と会話しながら、上から順に進めてください。
> RISE「AI自動化講座」11回目の配布物。受講生は「このURLを読んで、書いてある通りに進めてください」と送るだけ。
> この URL（https://ryoya9595.github.io/ai-jidoka-kouza/files/11-kouza-kaisetsu.md）を渡されたら、`curl -fsSL <URL>` で全文を取得して読む。**作業フォルダには保存しない**（画面に出して読むか、一時フォルダに置く）。
> 受講生が次のように送ってきたときも、この手順書の内容で進める：
>
> --------------
> 講座メモのフォルダを読んで、質問に答えるスキルを作りたい。答える時は、どのメモに書いてあったかも教えてほしい。メモに書いていないことは「メモにはありません」と答えてほしい。
> --------------

---

## 0. ゴール

作業フォルダの中に、**講座で学んだ内容を覚えておいて、質問すると答えてくれるスキル** `my-kouza` を作る。

- 「あの回で○○について何て言ってたっけ？」に、動画を見返さずに答えてもらえる
- 答えるときは **どのメモに書いてあったか** を示す
- メモに無いことは **「メモにはありません」** と答える（もっともらしい作り話をしない）

この考え方は、講座に限らず **自分の仕事のマニュアル・お客さんからのよくある質問** にもそのまま使える。

終わったときの形：

```
作業フォルダ/
├── 講座メモ/                      … 講座で学んだことを入れる場所（自分だけのメモ）
│   └── 講座の要点.md              … メモが無い人は、ここに要点を書く
└── .claude/skills/my-kouza/
    └── SKILL.md                   … 講座解説スキル
```

---

## 1. 守ること（最優先）

- **受講生はパソコン初心者。** 専門用語を避け、短く・やさしい日本語で話す。**1〜3手順ずつ** 出して「できた」を待つ。
- **講座の内容は受講生が自分だけで使うもの。** 講座メモや、講座の内容を読み込ませたスキルを、他の人に共有したり、ネット上に公開したりしない。公開用のリポジトリ（第20回で作るもの）にも入れない。作業フォルダは GitHub の **非公開** リポジトリなので、自分で使う分には問題ない。
- **講座の動画の文字起こしや、講座の資料そのものを作業フォルダに入れるよう促さない。** 入れるのは受講生が自分で取ったメモ・要点でよい。
- スキルの置き場は **作業フォルダの `.claude/skills/my-kouza/SKILL.md`**（パソコン全体の `~/.claude/skills` には置かない。スマホ・自動実行でも同じスキルを使えるようにするため）。
- 同じ名前のスキルがすでにあれば、中身を見せて確認してから上書きする。
- ファイルの作成・編集は Write / Edit ツールで行う（Windows の PowerShell のリダイレクトは文字化けするので使わない）。文字コードは UTF-8。
- 秘密の情報（パスワード・トークン）をメモやスキルに書かない。

---

## フェーズ1：確認（読むだけ・何も変更しない）

Claude Code が自分で確認すること：

1. 今のフォルダが受講生の作業フォルダか（`CLAUDE.md` と `.claude/skills/` がある）。無ければ「作業フォルダを開き直してください」と案内して止まる
2. `講座メモ/` フォルダがすでにあるか。あれば中のファイル名を一覧にする
3. `.claude/skills/my-kouza/` がすでにあるか

受講生に伝える：

> 自分用の「講座解説スキル」を作ります！
> 講座で学んだことをメモとして入れておくと、「あの回で何て言ってたっけ？」と聞けば、動画を見返さずに答えてくれるようになります。
> 手順は3つです。①講座メモのフォルダを作る → ②スキルを作る → ③質問して試す。

---

## フェーズ2：講座メモのフォルダを作って、メモを入れる

1. 作業フォルダに `講座メモ/` を作る（すでにあればそのまま使う）
2. 受講生に聞く：

> 作業フォルダに「講座メモ」フォルダを作りました。ここに講座で学んだことを入れていきます。
> 講座を見ながら取ったメモはありますか？
> ・ある → そのメモ（テキスト・Word・メモアプリの文章など）をこのフォルダに入れるか、ここに貼り付けてください。私がファイルにします
> ・まだない → 大丈夫です！今覚えている範囲で、各回の要点を一緒に書いていきましょう

3. **メモがある場合**
   - 貼り付けられた文章は、1回分ずつ `講座メモ/<回の番号>_<テーマ>.md` に保存する（例：`講座メモ/03_作業フォルダ.md`）。回が分からなければ `講座メモ/メモ_<日付>.md` でよい
   - Word などのファイルを入れてもらった場合は、そのまま置いてよい（スキルが読める形にする必要があれば、`.md` にも書き出す）
4. **メモがまだ無い場合**
   - 受講生に、覚えている回から順に **「その回で一番大事だと思ったこと」を1〜3行** で話してもらう（1回につき1問。全部そろわなくてよい）
   - 聞いた内容を `講座メモ/講座の要点.md` に次の形で書く：

```markdown
# AI自動化講座 各回の要点（自分用メモ）

## 第3回 作業フォルダ
- スキルは作業フォルダの `.claude/skills/<名前>/SKILL.md` に置く（パソコン全体の `~/.claude/skills` には置かない）
- 合言葉は2つ：「GitHubの最新を取り込んで」「GitHubに上げて」

## 第8回 スキル作成
- （受講生が覚えていることを1〜3行）

## 第10回 日報
- （受講生が覚えていることを1〜3行）
```

   - 上の例の第3回の2行は、作業フォルダの `CLAUDE.md` に書いてある内容なので、そのまま書いてよい（あとで「スキルの置き場はどこだっけ？」のテストに使う）
   - 覚えていない回は見出しだけ作って「（あとで追記）」と書く。あとから足せると伝える

5. 入れたファイルの一覧を見せて確認：

> 講座メモに {件数} 件入れました：{ファイル名の一覧}
> 次に、このメモを読んで答えるスキルを作ります。

## フェーズ3：スキル `my-kouza` を作る

1. 「作業フォルダの `.claude/skills/my-kouza/SKILL.md` に作りますね」と一言伝えて OK をもらう
2. 下の「インストールするスキル」を、`.claude/skills/my-kouza/SKILL.md` として保存する（```markdown の囲みの「中身だけ」。囲みの行 ``` は含めない）
3. 受講生が「スキル作成スキル（/my-skill-create）で作りたい」と言った場合は、それでもよい。ただし出来上がりが次の3点を満たしているか確認する：①講座メモのフォルダを全部読む ②どのメモに書いてあったかを示す ③メモに無いことは「メモにはありません」と答える

### インストールするスキル

```markdown
---
name: my-kouza
description: 作業フォルダの「講座メモ」を読んで、講座の内容についての質問に答える。答えるときは、どのメモに書いてあったかを示す。メモに書いていないことは「メモにはありません」と答える。「講座で○○って何て言ってた？」「あの回の内容教えて」「講座メモから探して」「講座解説」「/my-kouza」で使う。
---

# my-kouza — 自分用の講座解説

講座で学んだことを「講座メモ」から探して答える、自分専用の質問窓口。

## 使う材料
- 作業フォルダの `講座メモ/` にあるファイル全部（`.md`・`.txt` など。サブフォルダも含む）
- 質問が来るたびに、毎回フォルダの中を読み直す（メモが増えていることがあるため）

## 手順
1. `講座メモ/` の中のファイルを一覧にして、全部読む
2. 質問に関係する箇所を探す（言い回しが違っても、同じ意味なら拾う）
3. 見つかったら、次の形で答える：
   - 答え（やさしい日本語で、結論から、短く）
   - 出どころ：「📄 講座メモ/<ファイル名> の『<見出し>』」のように、どのメモのどこに書いてあったかを示す。複数あれば全部示す
   - メモの該当部分を、必要なら1〜3行だけ引用する
4. 見つからなかったら、**「メモにはありません」** と答える。そのうえで、
   - 似た内容がメモにあれば「近いものとして、○○のメモに△△とあります」と添える
   - 「この内容をメモに足しますか？」と聞き、本人が答えを教えてくれたら `講座メモ/` に追記する
5. 質問が「どの回の話か分からない」ときは、メモの見出し（回のタイトル）を一覧で見せて選んでもらう

## こだわり
- **メモに書いてあることだけを答える。** メモに無いことを、一般知識やもっともらしい推測で埋めない（AIは資料に無いことももっともらしく答えてしまうことがあるため、ここが一番大事）
- 一般知識として補足したいときは、答えとは分けて「※ここからはメモに無い、一般的な補足です」と明示する。聞かれていなければ補足しない
- 出どころ（どのメモか）は毎回必ず示す

## やらないこと
- 講座メモの中身や、このスキルを、他の人に共有したり、ネット上・公開用のリポジトリに出したりしない（講座の内容は自分だけで使う）
- 講座メモを勝手に書き換えたり消したりしない（追記は本人の OK をもらってから）
- 秘密の情報（パスワード・トークン・個人情報）をメモに書かない
```

4. 保存したら伝える：

> できました！「/my-kouza」で呼び出せます。
> 「講座で○○って何て言ってた？」のように普通に聞いてもらっても大丈夫です。

---

## フェーズ4：質問して試す

その場で2つ試してもらう（新しいセッションの方が確実に読み込まれる。出てこなければ新しいセッションで試してもらう）。

1. **メモにあることを聞く**

> 試しに聞いてみてください：「スキルの置き場はどこに置くんだっけ？」

   → 答えと一緒に「📄 講座メモ/講座の要点.md の『第3回 作業フォルダ』」のように **出どころ** が出れば OK

2. **メモに無いことを聞く**

> 次に、メモに書いていないことを聞いてみてください。例：「講座の第99回は何の話？」

   → **「メモにはありません」** と返ってくれば OK。もっともらしく答えてしまったら、SKILL.md の「こだわり」が読まれているか確認し、直す

3. 「ここ違う」があれば、その場で SKILL.md を直す

---

## フェーズ5：完了報告

最後に短く伝える：

> 自分専用の講座解説スキルができました！🎉
> ・講座メモに書き足したいことがあれば、「講座メモに足して」と言ってください
> ・講座だけでなく、自分の仕事のマニュアルや「お客さんからよく聞かれること」を入れたフォルダでも、同じ作り方で質問窓口が作れます
> ・最後に「GitHubに上げて」と言ってもらうと、スマホや自動実行からも使えるようになります
>
> ⚠️ 注意：講座メモとこのスキルは、自分だけで使ってください。講座の内容を他の人に共有したり、ネット上に公開したりしないようにお願いします（作業フォルダは非公開なので、自分で使う分には問題ありません）。

## 付録：うまくいかないとき

| 症状 | 原因 | 対処 |
|---|---|---|
| `/my-kouza` が一覧に出ない | 作った直後で読み込まれていない | 新しいセッションで試す。置き場所が `作業フォルダ/.claude/skills/my-kouza/SKILL.md` か、SKILL.md の一番上が `---` で始まっているか確認 |
| メモに無いことも答えてしまう | 「こだわり」が弱い／質問の仕方が広い | SKILL.md の「メモに書いてあることだけを答える」を確認。質問に「メモから探して」を添えてもらう |
| メモに書いてあるのに「ありません」と言う | 言い回しの違い／ファイルを読んでいない | `講座メモ/` の中を一覧にして、全部読み直してから答える。該当しそうな見出しを見せる |
| Word のメモが読めない | 形式の問題 | 中身をコピーして貼り付けてもらい、`.md` にする |
| スマホから使えない | GitHub に上げていない | 「GitHubに上げて」をしてから、スマホで「GitHubの最新」の状態で試す |
