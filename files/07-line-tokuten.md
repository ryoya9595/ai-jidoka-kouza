# Claude Code 向け手順書：LINE登録者向けの特典を作る

> 🤖 **Claude Code へ**：受講生がこのURLだけを貼って送ってきたら、これが今回の手順書です。curl（Windows は curl.exe）で全文を取得して、要約せず原文のまま読み、上から順に、1〜3手順ずつ受講生に確認しながら進めてください。受講生はパソコン初心者なので、やさしい言葉で短く話してください。手順書そのものは作業フォルダに保存しないでください。

> この手順書は **Claude Code が読んで実行するためのもの** です。受講生と会話しながら、上から順に進めてください。
> RISE「AI自動化講座」07回目の配布物。受講生は「このURLを読んで進めて」と貼るだけ。
> このURL（https://ryoya9595.github.io/ai-jidoka-kouza/files/07-line-tokuten.md）を渡されたら、`curl -fsSL <URL>` で全文を取得して読む。**この手順書そのものは作業フォルダに保存しない**（作るのは特典だけ）。

---

## 0. ゴール

AI秘書に特典のアイデアを出してもらい、1つ選んで、**スマホで見やすい1ページの特典（HTML）と、そのPDF版** を作る。

終わったときの形：

```
成果物/
└── 特典/
    └── {特典名}/
        ├── index.html   … スマホで見る用（後の回でURLにする）
        └── {特典名}.pdf … そのまま配れるPDF版
```

---

## 1. 守ること（最優先）

- **受講生はパソコン初心者。** 専門用語を避け、短く・やさしい日本語で話す。**1〜3手順ずつ** 出して「できた」を待つ
- **この回で作るのは「チェックリスト」「テンプレート集」「〇〇のやり方をまとめたミニ資料」のどれか。** 「診断」は第17回で「診断ツール」として本格的に作るので、この回では作らない。受講生が診断を選びたがったら「診断は後の回で、もっと本格的なものを作ります！今回は別の形にしましょう」と案内する
- 特典の中身は **受講生の発信を見ている人が「これは欲しい」と思えるか** が基準。見た目の豪華さより、誰のどんな困りごとに効くかを優先する
- **パスワード・カード番号・住所・電話番号・お客さんの個人情報は、特典に書かない・聞かない**
- 特典は **HTML 1ファイル**（CSS・JS は中に書く）。外部のライブラリ・Webフォント・外部画像は使わない（後の回でそのままURLにするため）
- **数字・統計・「〇〇%」「〇〇円」などのデータは、根拠が無いものを書かない。** 書いた場合は、最後に受講生に確認してもらう（ステップ6）
- 他人の文章・画像をコピーして入れない
- ファイルの作成・編集は Write / Edit ツールで行う（文字コードは UTF-8）
- **何かをインストールする前に必ず聞く**（PDF化で必要になった場合）

---

## 2. 最初の確認（読むだけ）

Claude Code が自分で確認すること：

1. 作業フォルダに `CLAUDE.md` と `私のプロフィール.md` があるか
   - `CLAUDE.md` が無い → 「先に『作業フォルダセットアップ』（03回目）を済ませてください」と案内して止まる
   - `私のプロフィール.md` が無い → AI秘書（04回目）が未作成。止まらずに、受講生に **発信のジャンルと届けたい人** を1問で聞いて進める（「まだ発信ジャンルが決まっていない人は、興味のあるジャンルで試しに作るだけでも大丈夫です」と添える）
2. `成果物/特典/` があるか。無ければ作る（Write で `.gitkeep` を置くか、フォルダ作成）

受講生への最初のあいさつ：

> これから、公式LINEの登録特典を作ります！
> 流れは「アイデアを5つ出す → 1つ選ぶ → 作る → 直す → PDFにもする」です。15分くらいで終わります。
> まず、プロフィールをもとにアイデアを出しますね。

## 3. ステップ1：特典のアイデアを5つ出す

受講生から次の指示文が来たものとして動く（講座の動画で見せた指示文。受講生が別の言葉で言っても同じ）：

```
私の発信を見てくれている人に向けて、公式LINEの登録特典のアイデアを5つ出してください。すぐに作れて、受け取った人がすぐ使えるものがいいです。
```

`私のプロフィール.md`（発信のジャンル・届けたい人・面倒な作業）を読んで、**5つ** 出す。形は「チェックリスト」「テンプレート集」「ミニ資料」のどれか（診断は入れない）。

1つにつき、次の3行で書く：

- **①〇〇チェックリスト**（形：チェックリスト）
  - 中身：〇〇するときに確認する10項目
  - 効く相手：〇〇で困っている人に、〇〇という場面で

出したら聞く：

> この中から1つ選んでください（番号でOKです）。「③と④を合体」のような注文でも大丈夫です。
> ※「診断」は後の回（第17回）で本格的に作るので、今回はこの中から選んでください。

---

## 4. ステップ2：中身を決める（1回だけ確認）

選ばれた特典について、作る前に **タイトル案と項目の一覧** を見せて、1回だけ確認を取る：

> こんな中身で作ります。足したい・減らしたい項目はありますか？（無ければ「OK」でOKです）
> **タイトル：**〇〇
> **項目：**1. … 2. … 3. …

- 項目は **5〜10個**。多すぎると最後まで読まれない
- 各項目は「何をするか」が1行で分かる言い方にする（専門用語は使わない）
- 最後に「発信者からの一言」と「公式LINEで質問を受け付けています」の欄を入れる（LINE のURLは後の回で入れるので、今は文章だけ）

---

## 5. ステップ3：作る

受講生から次の指示文が来たものとして作る（〇〇は選んだ特典名）：

```
〇〇（選んだ特典）を作ってください。スマホで見やすい1ページにしてください。
```

### 作るファイル

`成果物/特典/{特典名}/index.html`（特典名は日本語でよい。例：`成果物/特典/時短料理の買い物チェックリスト/index.html`）

### 作り方の条件

- HTML 1ファイル。CSS と JS は `<style>` `<script>` で中に書く。外部ファイル・CDN・Webフォント・外部画像を使わない
- `<meta name="viewport" content="width=device-width, initial-scale=1">` を入れる
- スマホで見やすく：本文の文字は 16px 以上、行間ゆったり、横幅は画面に合わせる（横スクロールが出ない）
- 構成：
  1. タイトル＋ひとこと（誰向け・何に使うか）
  2. 本文（チェックリストなら項目ごとにチェックボックス。テンプレート集なら「コピー」ボタン付きの文例。ミニ資料なら見出し＋短い説明）
  3. 発信者からの一言
  4. 「公式LINEで質問を受け付けています」の案内（ボタンのリンク先は `#` のままにして、後の回で差し替える旨をコメントで残す）
- チェックボックスの状態は、ページを閉じても残るようにしてよい（`localStorage`。使えない環境でもエラーにならないように `try/catch` で囲む）
- **印刷用の見た目** を `@media print` で用意する（PDF化で使う）：背景色は白、ボタンは非表示、A4縦でおさまる文字サイズ
- 装飾は絵文字・CSSの図形・インラインSVGでつける（外部画像は使わない）
- 色は受講生の発信の雰囲気に合わせる（プロフィールにヒントが無ければ、やさしい2色＋白）

作ったら伝える：

> 特典の1ページができました！右上の **プレビュー** で見てみてください。
> スマホ表示にも切り替えて、読みやすいか確認してみてください。

## 6. ステップ4：直す（1〜2回）

受講生の感想を聞いて直す。例：

> 気になるところがあれば、そのまま日本語で言ってください。例：
> ・「最後に公式LINEで質問を受け付けていますと入れて」
> ・「文字をもう少し大きくして」
> ・「項目を1つ足して：〇〇」
> ・「もっとやさしい雰囲気にして」

- 直すたびにプレビューで確認してもらう。「OK」が出たら次へ
- 2回直しても良くならないときは「一度シンプルな形に戻してから作り直します」と提案する

## 7. ステップ5：PDFにもする

受講生が「PDFにもして」と言ったら（言わなくても、こちらから「PDFでも配れるようにしておきますね」と進めてよい）：

1. **ブラウザが入っているか確認**して、入っていれば印刷機能でPDF化する（インストール不要）
   - Mac（Chrome）：`"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu --no-pdf-header-footer --print-to-pdf="<保存先の絶対パス>.pdf" "file://<index.htmlの絶対パス>"`
   - Windows（Chrome）：`& "C:\Program Files\Google\Chrome\Application\chrome.exe" --headless --disable-gpu --no-pdf-header-footer --print-to-pdf="<保存先の絶対パス>.pdf" "file:///<index.htmlの絶対パス>"`
   - Edge しか無い Windows：`chrome.exe` の代わりに `"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"`
2. 保存先：`成果物/特典/{特典名}/{特典名}.pdf`
3. できたPDFを開いて（Mac `open`／Windows `start`）、受講生に確認してもらう：
   > PDF版も作りました！開いたので、文字が切れていないか見てみてください。
4. コマンドでうまくいかないとき（ブラウザが見つからない・文字化け）は、受講生に手でやってもらう：
   > ブラウザで特典のページを開いて、**Cmd+P（Windows は Ctrl+P）→「PDFとして保存」** を押してください。保存先は `成果物/特典/{特典名}/` にしてください。
5. 何かを新しくインストールする方法（`wkhtmltopdf`・Node のパッケージなど）は、**受講生に「何を・なぜ入れるか」を1行で伝えてOKをもらってから** にする。急がないなら 4 の手動で十分

## 8. ステップ6：数字とデータの自己チェック（必ずやる）

特典は **受講生の名前で配るもの**。AI はもっともらしい数字を書いてしまうことがあるので、渡す前に受講生自身の目でチェックしてもらう。

1. 特典の中に入っている **数字・統計・金額・期間・「〇〇によると」などの出典っぽい表現** を全部抜き出して一覧にする（無ければ「数字は入っていません」と伝える）
2. 受講生に見せて確認してもらう：
   > 特典の中に、次の数字・データが入っています。**正しいか、自分で確認できるものか** を見てください。
   > ・〇〇（本文の「…」の部分）
   > 確認できないものは、消すか、「目安」「例えば」のようなやわらかい言い方に直します。どうしますか？
3. 受講生の答えどおりに直す。確認できないものは **消す・やわらげる** のどちらかにする（そのまま残さない）
4. あわせて、健康・お金・法律に関わる内容があれば、「必ず〇〇になります」のような言い切りを「〇〇しやすいです」「〇〇という考え方もあります」に直す

>
> **やってみよう：** 完成した画面のスクショを、アウトプット部屋に投稿してみてください。

そのあとで：

> 最後に「**GitHubに上げて**」と言ってもらえれば、この特典が GitHub にも保存されます。

受講生が「GitHubに上げて」と言ったら、`CLAUDE.md` の合言葉のルールどおりに上げる（上げる前に、秘密の情報が混ざっていないか確認する）。

## 付録：うまくいかないとき

| 症状 | 対処 |
|---|---|
| アイデアが受講生のジャンルとずれている | `私のプロフィール.md` の「届けたい人」「面倒な作業」を読み直して、「〇〇で困っている人向け」と相手を1人に絞って出し直す |
| 受講生が「診断を作りたい」と言う | 第17回で診断ツールを本格的に作ると伝え、今回はチェックリスト・テンプレート集・ミニ資料から選んでもらう |
| プレビューに出ない | 「作ったページをプレビューで開きます」と言って開く。だめなら `index.html` をダブルクリックで開いてもらう |
| PDFの文字が切れる・ボタンが印刷される | `@media print` を見直す（ボタン `display:none`、文字サイズを少し下げる、`page-break-inside: avoid`） |
| 日本語のフォルダ名でコマンドが失敗する | パスを `"` で囲む。それでもだめなら英語のフォルダ名（例：`tokuten-01`）にして、受講生に一言伝える |
